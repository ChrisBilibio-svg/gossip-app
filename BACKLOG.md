# Fofoca — Build Backlog

Single source of truth for the two autonomous build loops. Each loop picks the **top
unchecked item in its own lane**, ships it, checks it off, and moves on.

## How the loops cooperate (read every iteration)

- **Always `git pull --rebase origin main` before starting.** If there's a conflict, STOP and surface it — never force.
- **Lanes are file-scoped** so the agents rarely touch the same files:
  - 🔵 **Hermes lane (backend / security / scale):** `supabase/migrations/`, `src/lib/`, `scripts/`, `gossip-admin/`, backend tests in `tests/`.
  - 🟣 **Claude Code lane (UI / screens):** `src/screens/`, `src/components/`, `src/theme/`, UI wiring in `App.tsx`.
  - 🟢 **Test & Quality lane:** `tests-ui/` (jest-expo + React Native Testing Library *runtime* tests), `jest.config.cjs`, `babel.config.cjs`, `tests-ui/tsconfig.json`. **Reads** `src/**`/`App.tsx` to test them but **never edits app code**. Run with `npm run test:ui` (+ `npm run typecheck:ui`). One shared touchpoint: testing devDeps + `test:ui`/`typecheck:ui` scripts in `package.json` (the existing `test`/`typecheck` scripts are left untouched). If a component needs a test-only `testID` to be reachable, file a `[handoff]` to the UI lane — don't add it directly.
- **Cross-lane handoffs:** if a backend change needs a UI follow-up (or vice-versa), check your item off and add a paired item to the *other* lane tagged `[handoff]` with a one-line note. Don't reach into the other lane's files yourself.
- **Keep each change small, atomic, typechecked, and tested.** Never commit a broken build (`tsc --noEmit` + `node --test tests/*.test.mjs` must pass). Commit + push each item separately.
- **STOP and ask the human before:** applying a NEW Supabase migration (the human runs those by hand), any destructive/irreversible action, or any product / pricing / legal / brand decision.
